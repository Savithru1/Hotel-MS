# P1.11 design: manager dashboard, notifications, background jobs

Status: working design for sub-phase P1.11 (written 2026-11-27). Detail of the plan is in `IMPLEMENTATION_PLAN.md` (P1.11). This file records how it is built on top of the code that exists.

## Conventions found in the code (follow these)

- Files are `<entity>.model.ts`, `<entity>.service.ts`, `<entity>.routes.ts` (handlers inline in routes, no controllers). Zod schemas live in `packages/validation`, DTOs in `packages/shared-types`, constants in `packages/constants`. (CLAUDE.md names `controller.ts`/`validation.ts`; the code already differs, so keep the code's convention.)
- Every property model applies `tenantPlugin`; no `req.body` reads (use `validate()` / `req.validated`); `HttpError` helpers; `transition()` for status changes; `recordAudit()` for sensitive actions; no `Model.collection`.
- Money is integer paise. Dates are `YYYY-MM-DD` in the property timezone (`todayIn(tz)`, `localDateTimeToUtc`).

## Decisions

1. Audit log is readable by management roles (`property_admin`, `manager`). Easy to narrow to `property_admin` only if the owner prefers.
2. Revenue = posted bill lines (net of GST, credit notes subtracted on their issue date, by department); payments and refunds are shown separately as cash flow. Bill lines are only posted when a bill is opened, so a `billing.sync_open` job opens and syncs every checked-in booking's bill periodically, and the API returns `lastSyncedAt`.
3. Occupancy denominator = today's active room count (room status history is not stored); labelled on screen.
4. `background_jobs` is tenant-scoped (every job belongs to one property). The worker claims inside `runAsPlatform`, then runs the handler inside the job's property context with a system principal.
5. SLA thresholds (starting values, owner to confirm): housekeeping normal 30 / urgent 15 min; maintenance low 240, medium 120, high 60, urgent 30; food reuses `LATE_ORDER_MINUTES`.
6. Notification triggers come from in-process bus events; a crash can lose one. The SLA scan is the safety net. A transactional outbox is the stronger fix if ever needed.
7. Housekeeping gets manager reassign while `in_progress` (maintenance already allows it). Events carry `assignedTo`.

## Data models

**notifications** (tenantPlugin): `recipient {kind:'staff', id}`, `type`, `title` (<=120), `body` (<=300), `link {kind, id}` (ids only), `dedupeKey`, `readAt|null`, `expireAt|null`, timestamps. Indexes: `(propertyId, recipient.id, readAt, createdAt:-1)`; unique partial `(propertyId, recipient.id, dedupeKey)`; TTL on `expireAt` (set to `readAt + 30d` when read; unread items removed by the cleanup job after 90 days). Fan-out per person at write time.

**background_jobs** (tenantPlugin): `type`, `payload`, `dedupeKey`, `runAt`, `status` pending|running|done|failed, `attempts`, `maxAttempts` (5), `lockedUntil`, `lockToken`, `lastError` (<=500 chars, no stack), `recurring {everyMs}|null`. Indexes: `(status, runAt)`; unique partial `(propertyId, dedupeKey)`.

Also: `slaRemindedAt: Date|null` and index `(propertyId, status, slaRemindedAt, createdAt)` on service requests, maintenance issues and food orders; audit_logs index `(propertyId, actor.id, at)`.

## Worker

- Claim in `runAsPlatform` with one `findOneAndUpdate` on `pending && runAt<=now` OR `running && lockedUntil<now` (crash recovery); set lease 60 s, new `lockToken`, `$inc attempts`.
- Finish filtered on `{_id, lockToken}` so a worker whose lease expired cannot overwrite. Success: `done`, or recurring: back to `pending` at `now+everyMs`, attempts 0. Failure: backoff `min(30s*2^(attempts-1), 30min)`; at `maxAttempts` becomes `failed` + audit + manager notification.
- Guarantee: never two at once, a finished job never reruns; crash mid-run reruns after the lease (at-least-once), so handlers are idempotent.
- `createWorker({clock, pollMs, handlers, logger})` with `tick()`, `start()` (unref'd interval, skips if a tick is in flight), `stop()`. `JOBS_ENABLED` env (false in test, true otherwise), `JOB_POLL_MS=5000`.
- `scheduler.ensure()` upserts recurring jobs per active property: `sla.scan` 1 min, `notifications.cleanup` daily, `billing.sync_open` 15 min (`$setOnInsert` on dedupeKey); rerun every 10 min for new properties.
- SLA scan: open items older than the threshold with `slaRemindedAt:null` (limit 200); claim each with `findOneAndUpdate({_id, slaRemindedAt:null})`, only the winner notifies managers.

## API (all under `/api/v1`)

Management only (`requireRole(...MANAGEMENT)`): `GET /manager/overview?date=`, `GET /manager/stats/occupancy?from&to`, `GET /manager/stats/revenue?from&to`, `GET /manager/stats/response-times?from&to`, `GET /audit-logs?from&to&action&actorId&targetType&targetId&page&limit(<=100)`. Range inclusive, <=92 days, `from>to` is 400, default today.

Any signed-in staff member, always filtered by `recipient.id = me`: `GET /notifications?unread&page&limit`, `GET /notifications/unread-count`, `POST /notifications/:id/read`, `POST /notifications/read-all`. Someone else's id is 404.

- Overview: `{date, timezone, rooms:{active, byStatus}, occupancy:{occupied, sellable, rateBp}, arrivals:{expected, checkedIn}, departures:{expected, checkedOut}, inHouse, queues:{housekeeping|maintenance|kitchen|spa:{pending, completedToday, escalated, urgent}}, escalations:[...]}`. `completedToday` uses the property-local day.
- Occupancy per day: count `RoomNight` for the date (booking checked_in/checked_out for past and today; confirmed/pending shown as on the books for future), two queries (no `$lookup`, tenant plugin blocks it). `rateBp = round(occupied*10000/sellable)`.
- Revenue per day and department (rooms, food, spa_recreation, other): `$unwind lines`, match `serviceDate`; credit notes subtracted on `issuedAt` local date, department from the original line. Returns taxable, tax, total, `payments:[{date, receivedPaise, refundedPaise}]` (local `createdAt` date), `lastSyncedAt`.
- Response times (items created in range, cancelled excluded): housekeeping first action = first `in_progress` history entry minus `createdAt`, done = `completedAt - createdAt`; maintenance first action = first `assigned` (else `in_progress`), done = `resolvedAt - createdAt`; kitchen = `preparingAt`, `deliveredAt`. `n=0` gives `null`, never 0. Whole seconds. Spa excluded.
- Live delivery: after insert, emit `notification.created` to `audience:{managers:false, staffIds}` over the existing `p:{pid}:user:{uid}` rooms; the client refetches the unread count.
- Triggers: escalated (housekeeping/maintenance) -> managers; assigned/reassigned -> the assignee; maintenance created urgent/high -> managers; SLA job -> managers; job failed for good -> managers.

## Staff app

`pages/manager/DashboardPage`, `QueuePanel`, `AssignDialog`, `StatsPage` (+ occupancy/revenue/response tables, no chart library), `AuditLogPage`, `EditStaffDialog` (name, role, departments; `updateStaffSchema` exists), `components/NotificationBell` + `NotificationPanel` in the app layout for every role. `auth/permissions.ts` gets `/manager`, `/manager/stats`, `/audit` for management; managers land on `/manager`. "No data" is shown, never 0, when a figure has no data.
