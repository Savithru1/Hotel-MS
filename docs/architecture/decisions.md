# Architecture decisions

One file, newest at the bottom. The full reasoning is in `IMPLEMENTATION_PLAN.md`; this records what was decided and when. Add a row whenever a decision changes.

| Date       | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Why                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2026-11-25 | **MongoDB is the only database** (Mongoose ODM). TTL indexes, transactions and GridFS cover tokens, jobs and files. No Redis or any other store.                                                                                                                                                                                                                                                                                                                          | Owner's non-negotiable requirement. A test in `tests/repo-structure.test.ts` fails if another database client or compose service appears.                                     |
| 2026-11-25 | Monorepo with pnpm workspaces: `apps/backend`, `apps/staff-app`, `apps/guest-app`, `packages/shared-types`, `packages/validation`, `packages/constants`. Workspace scope `@hospitality/*`.                                                                                                                                                                                                                                                                                | Matches the spec's folder structure.                                                                                                                                          |
| 2026-11-25 | **Shared packages are consumed as TypeScript source** (`exports` point at `src/index.ts`) and all workspaces use `moduleResolution: Bundler`.                                                                                                                                                                                                                                                                                                                             | No build step between packages. The backend will run through `tsx` in development and be bundled for production (decided in P1.2).                                            |
| 2026-11-25 | **TypeScript is pinned to 6.0.x** (not 7).                                                                                                                                                                                                                                                                                                                                                                                                                                | `typescript-eslint` 8.74 supports TypeScript below 6.1. Revisit when typescript-eslint supports 7.                                                                            |
| 2026-11-25 | ESLint 10 flat config + typescript-eslint + Prettier; Vitest for tests. `no-console` is an error.                                                                                                                                                                                                                                                                                                                                                                         | Standard modern toolchain; matches the "no console.log" rule.                                                                                                                 |
| 2026-11-25 | Local database is a **one-node replica set** in Docker (`pnpm db:up`), bound to `127.0.0.1` only. Tests will use an in-memory replica set.                                                                                                                                                                                                                                                                                                                                | Transactions (bookings, billing, check-out) require a replica set.                                                                                                            |
| 2026-11-25 | Multi-tenancy by `propertyId` enforced by a Mongoose plugin and request context (built in P1.2).                                                                                                                                                                                                                                                                                                                                                                          | Property data isolation is a hard requirement.                                                                                                                                |
| 2026-11-25 | Guest login: linked phone number + Booking ID, checked-in bookings only, behind a two-step `GuestVerifier` so SMS OTP can be added later. No QR codes in Phase 1.                                                                                                                                                                                                                                                                                                         | Owner decision. See plan section 3.9.                                                                                                                                         |
| 2026-11-25 | Money is integer paise (INR); GST from effective-dated config, snapshotted on every bill line. Payments behind a `PaymentProvider` interface (Razorpay first).                                                                                                                                                                                                                                                                                                            | See plan sections 3.4 and 3.7.                                                                                                                                                |
| 2026-11-25 | Phase 1 is the hotel management system only. AI trip planner, recommendations, Maps and the public booking site are deferred.                                                                                                                                                                                                                                                                                                                                             | Owner decision.                                                                                                                                                               |
| 2026-11-25 | **Backend stack:** Express 5 (async errors need no wrappers), Mongoose 9, Zod 4 (one schema validates requests and generates the OpenAPI docs), pino for logs, helmet, cors allow-list, express-rate-limit (in-memory store, single instance), swagger-ui-express.                                                                                                                                                                                                        | Plan section 3.1. No Redis or other store; rate-limit counters stay in memory.                                                                                                |
| 2026-11-25 | **Backend runs through `tsx` in development and is bundled with `tsup` for production** (workspace packages are bundled in, third-party packages stay external).                                                                                                                                                                                                                                                                                                          | Decision deferred from P1.1. Matches the "shared packages are TypeScript source" rule.                                                                                        |
| 2026-11-25 | **One API response envelope:** `{ success, data }` or `{ success: false, error: { code, message, details? }, requestId }`, typed in `packages/shared-types`. Error messages never include submitted values or internals.                                                                                                                                                                                                                                                  | Consistent client handling and no data leaks in errors.                                                                                                                       |
| 2026-11-25 | **Tenant isolation is a Mongoose plugin plus request context.** Every query is ANDed with the current property; documents are stamped on create; `bulkWrite`, pipeline-style updates, `$rename` of `propertyId`, and cross-collection or server-wide aggregation stages are refused for property requests; replacements and upserts are forced into the current property. `runAsPlatform` is the only way to see every property and is easy to search for.                | Review of the plugin found that replacing a document, or upserting with `$setOnInsert`, could orphan a record or move it to another property. Both are now closed and tested. |
| 2026-11-25 | **A lazily returned Mongoose query is started inside the context** (`runWithTenant(id, () => Model.find())` works).                                                                                                                                                                                                                                                                                                                                                       | Queries only run when awaited; without this they would run after the context ended.                                                                                           |
| 2026-11-25 | **Raw `Model.collection` access is banned by lint** in backend source.                                                                                                                                                                                                                                                                                                                                                                                                    | It bypasses the tenant plugin.                                                                                                                                                |
| 2026-11-25 | **Backend tests use an in-memory MongoDB replica set** (one shared instance, one throwaway database per test file). The first run downloads a MongoDB binary of about 780 MB into `~/.cache/mongodb-binaries`; CI caches it.                                                                                                                                                                                                                                              | Transactions need a replica set, and tests must not need Docker.                                                                                                              |
| 2026-11-25 | **State machines are tables of allowed moves** with an optimistic, conditional update and an append-only `history[]`. Racing moves have exactly one winner and the loser gets 409.                                                                                                                                                                                                                                                                                        | Plan section 3.5.                                                                                                                                                             |
| 2026-11-25 | **Audit log is append-only** (updates and deletes are refused) and takes the actor, request id and IP from the request context.                                                                                                                                                                                                                                                                                                                                           | Plan section 6 security checklist.                                                                                                                                            |
| 2026-11-25 | `socket.ts` is not created in P1.2. The Socket.IO gateway is built in P1.4.                                                                                                                                                                                                                                                                                                                                                                                               | A stub file would be fake code.                                                                                                                                               |
| 2026-11-26 | **Auth model:** staff sign in with property link name + email + password. Access JWT (15 min, HS256, issuer and audience checked) says only who is calling; role, departments and active state are re-read from the database on every request. Refresh tokens are random, stored as keyed hashes in `refresh_tokens` with a TTL index, rotated on use, a replayed token revokes its whole family, and a session ends 30 days after sign-in however often it is refreshed. |
| 2026-11-26 | **Staff management only works downwards** by role rank; `platform_admin` is never assignable through the API; a new account gets a one-time temporary password and must change it before using anything else.                                                                                                                                                                                                                                                             |
| 2026-11-26 | **Realtime:** services emit typed events on an in-process bus; only the gateway touches sockets. The server decides rooms (managers join the managers room, others their department rooms), clients cannot join rooms or publish, payloads carry ids only, and a connection closes when its access token expires (the app renews and reconnects). The Mongo adapter is available behind `SOCKET_ADAPTER=mongo`.                                                           |
| 2026-11-26 | **Double-booking prevention:** one `room_nights` document per room per night with a unique index, written together with the booking in a transaction. Nights are plain `YYYY-MM-DD` dates in the property timezone; check-out day is not a night.                                                                                                                                                                                                                         |
| 2026-11-26 | **Room status** follows a transition table and is changed only through `transition()`; bookings, housekeeping and maintenance change it inside their own transactions and announce it after commit.                                                                                                                                                                                                                                                                       |
| 2026-11-26 | **GST rules** are effective-dated and append-only per property; defaults are starting values pending accountant sign-off.                                                                                                                                                                                                                                                                                                                                                 |
| 2026-11-26 | **Known deviation:** the staff app stores the refresh token in `localStorage` (global web rule prefers an httpOnly cookie). To be revisited before go-live (P1.14): cookie refresh token + CSRF protection.                                                                                                                                                                                                                                                               |
